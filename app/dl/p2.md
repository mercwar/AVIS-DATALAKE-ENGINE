

# 📘 AVIS Public Tutorial — Page 2  
## 🌐 Browser Navigation & Search Controls

The AVIS Datalake Engine exposes its backend through **two public browser interfaces**. These portals allow users to explore tenant data, apply filters, and view metadata cards with ease.

---

## 🔒 Private Browser Workspace
The **Private Browser** is scoped to the authenticated user (`$google_user`).  

### Features
- **Global Search**: Matches substrings across filenames.  
- **Dropdown Filters**: Dynamically populated from filename tokens (ID, Keyword, Date, Time).  
- **Refine Inputs**: Manual entry fields for precision filtering (`YYYYMMDD`, `HHMMSS`).  
- **Pagination**: 10 files per page, preserving query parameters.  
- **View Details**: Routes to `print_view.php?owner=$google_user&file=<basename>`.

---

## 🌐 Public Browser Grid Portal
The **Public Browser** aggregates records across all registered user folders.

### Features
- **Publisher Filter**: Dropdown + refine input for usernames.  
- **Newest File Per User**: Engine sorts by modification time and displays the latest JSON.  
- **Empty Node Handling**: Displays “NO FILE AVAILABLE” cards for users without payloads.  
- **Pagination**: 10 publishers per page, preserving filters.  
- **Routing Links**:  
  ```
  print_view.php?owner={Publisher}&file={File_Basename}
  ```

---

## 📄 Example User Flow
1. **User selects Publisher** → Dropdown shows `Tran`.  
2. **Engine discovers file** → `node_avis_6a6da2e9abb39_20260801_074025.json`.  
3. **Browser displays metadata card** → Title, description, and “View Details” link.  
4. **Review Form renders full schema** → Identity, Architecture, Storage, Security, Contact.  

---

## ✅ Best Practices for Public Users
- Use dropdowns for quick filtering, refine inputs for precision.  
- Always preserve query parameters across pagination.  
- Expect “NO FILE AVAILABLE” cards for new users without payloads.  
- Trust the engine’s newest‑file logic to surface the most relevant data.
