# 📘 AVIS Public Tutorial — Page 1  
## 🌐 Routers, Switches & Engines

The AVIS Datalake Engine integrates with **routers** and **switches** to manage multi‑tenant data flows across distributed environments. This tutorial introduces the fundamentals of how public users interact with the system.

---

## 🔌 Routers: Entry Points into the Datalake
Routers act as **gateways** between external clients and the datalake engine.

- **Ingress Routers**: Accept incoming requests from public users.  
- **Egress Routers**: Deliver processed payloads back to clients.  
- **Load Balancing Routers**: Distribute traffic evenly across tenant directories.  

```text
Client → Ingress Router → AVIS Engine → Egress Router → Response
```





---

## 🔀 Datalake Switches: Internal Traffic Control
Switches manage **intra‑engine traffic**, ensuring that payloads are routed to the correct tenant directories.

- **Tenant Switches**: Direct requests to the correct user folder (`../RRU-AI/USER/{username}/`).  
- **Metadata Switches**: Route queries based on filename tokens (ID, Keyword, Date, Time).  
- **Diagnostic Switches**: Redirect faulty requests to error handlers.  





---

## ⚙️ Engines: Processing & Indexing Core
The **AVIS Engine** is the heart of the datalake system. It performs:

- **File Discovery**: Uses `glob()` to locate JSON payloads.  
- **Indexing**: Sorts files by modification time (`filemtime`).  
- **Filtering**: Splits filenames into searchable tokens.  
- **Pagination**: Limits results to 10 per page for performance.  





---

## 📄 Example Workflow
1. **User Uploads File** → `node_router_alpha_20260801_051700.json`  
2. **Ingress Router Accepts Request** → Passes to AVIS Engine.  
3. **Switch Routes Payload** → Directs to correct tenant folder.  
4. **Engine Indexes File** → Adds metadata to dropdown filters.  
5. **Public Browser Displays Card** → Title, description, and “View Details” link.  

---

## ✅ Best Practices
- Always configure `$user_loc` with a trailing slash (`/htdocs/MWAD/avis/`).  
- Use `DIRECTORY_SEPARATOR` for cross‑platform safety.  
- Skip only `.` and `..` directories, not nested folders.  
- Normalize filenames with `str_replace('-', '_', $name)` for consistent filtering.
