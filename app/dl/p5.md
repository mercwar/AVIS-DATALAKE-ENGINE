# 📘 AVIS Public Tutorial — Page 5  
## 🤝 Contributing & Community Practices

The AVIS Datalake Engine thrives on collaboration. Public users can extend routers, switches, and engines by contributing code, documentation, or payload schemas.

---

## 🔧 How to Contribute
- **Fork Repository** → Create your own copy to experiment safely.  
- **Create Branch** → Use descriptive names like `feature/router-enhancement`.  
- **Commit Changes** → Write clear commit messages explaining *why* the change was made.  
- **Open Pull Request** → Submit your branch for review. Include screenshots or code snippets.  
- **Review & Merge** → Collaborators review and merge approved PRs.  

---

## 📜 Contribution Standards
- **Code Style** → Follow PHP 8.2+ standards and PSR‑12 formatting.  
- **Documentation** → Update README tutorials when adding new features.  
- **Testing** → Validate changes with sample JSON payloads before submitting.  
- **Security** → Never commit sensitive credentials or private data.  

---

## 🌐 Community Practices
- **Issue Tracking** → Use GitHub Issues to report bugs or request features.  
- **Roadmap** → Planned enhancements include neon UI styling, metadata dashboards, batch reviews, and role‑based access.  
- **Communication** → Join repository discussions, share ideas, and collaborate on new features.

## ✅ Public User Checklist
- [ ] Run diagnostics (`diagnostic_uplink.php`) before uploading payloads.
