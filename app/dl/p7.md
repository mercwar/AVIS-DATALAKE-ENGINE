# 📘 AVIS Public Tutorial — Page 7  
## 🔐 Security & Access Control

The AVIS Datalake Engine integrates **security protocols** directly into routers, switches, and engines to protect tenant data and ensure safe public interactions.

---

## 🛡️ Core Security Layers

- **Encryption** → All JSON payloads should be encrypted at rest and in transit.  
- **Role‑Based Access Control** → Private browser visibility is limited to authenticated `$google_user`.  
- **Authentication Tokens** → Routers require valid tokens before allowing ingress traffic.  
- **Audit Logging** → Switches record every routing event for compliance and monitoring.  
- **Error Isolation** → Corrupted payloads are quarantined to prevent system‑wide crashes.  

---

## 🔒 Private Browser Security
- Filters and payloads are scoped to the authenticated user.  
- **Routing Links** include `owner=$google_user` to prevent unauthorized access.  
- Sensitive metadata fields (e.g., architect emails) are hidden unless explicitly permitted.  

---

## 🌐 Public Browser Security
- Displays only the **latest file per publisher**, reducing exposure of historical data.  
- Empty nodes show **“NO FILE AVAILABLE”** instead of leaking directory structures.  
- Publisher dropdowns are sanitized to prevent injection attacks.

## ✅ Best Practices for Public Users
- Always encrypt payloads before uploading.  
- Use role‑based permissions to restrict private data.  
- Monitor audit logs for unusual activity.  
- Run diagnostics regularly to confirm secure directory traversal.  
- Trust only validated payloads with complete security metadata.
